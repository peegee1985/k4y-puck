# K4Y Puck 0.4.22 / build 256 — start a obnova dotykového řadiče

Datum: 23. 10. 2026.

Nový log z 255 ukázal 2 444 úspěšných přenosů se stejným stavem 00 40 00 00: řadič zůstává v BIOSu, nevstoupí do CPU/RUN a neposílá dotykové pakety. Samotné odpovědi na I2C tedy nestačily k označení dotyku jako připraveného.

- Čtení registrů SPD2010 nyní odděluje výběr registru ukončený STOP a následné čtení s pauzou 200 µs. Oba přenosy i pauza jsou pod rekurzivním zámkem. Postup odpovídá aktuálnímu ovladači Espressifu a Arduino příkladu Waveshare.
- Připravenost vyžaduje zjištěný RUN nebo platná dotyková data. BIOS/CPU ji zruší, běžná prázdná či busy odpověď po RUN ji sama nezruší.
- Uvízlý BIOS/CPU už neobchází obnovu díky úspěšným ACK. Po trvajícím problému se resetuje pouze dotyk, nejvýše jednou za pět sekund. Funkční IMU a společná sběrnice se při této obnově neresetují.
- USB diagnostika zůstává aktivní. Hlasová oznámení jsou při tomto ověřování dál dočasně nahrazena původními tóny z 252.

Žádný firmware dotykového čipu se nepřepisuje ani nemaže. Není potřeba nové párování ani migrace backendu. Účinnost na fyzickém panelu zatím není potvrzená.

Ověření: všechny čtyři zdrojové CI prošly, včetně ESP-IDF 5.5.2 pro ESP32-S3, produkčního LVGL a rotací, core a web/Convex kontraktů. Test vykonává skutečnou čtecí, inicializační a obnovovací funkci; kontroluje STOP/pauzu/zámek, přehraje všech 2 444 BIOS odpovědí a ověřuje pět omezených pokusů o reset pouze dotyku. Dále pokrývá zdravý RUN bez prstu, platné souřadnice/uvolnění, vadné pakety, neúspěšný výběr registru a odklad dalších pokusů.
